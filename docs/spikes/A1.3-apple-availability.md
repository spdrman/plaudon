# A1.3 — Apple SpeechTranscriber and FoundationModels availability

**Status:** complete, with two real defects found and fixed.
**Date:** 2026-10-11. **Spec:** §2.3, §2.6, §11, §20.1.
**Bridge:** `native/apple-bridge/`. **Rust side:** `crates/ai-apple/`.
**Run it:** `scripts/probe-apple.sh [audio-file] [locale]`.

## Host the measurements were taken on

| | |
|---|---|
| OS | macOS 27.0.1, build 26A434 |
| Toolchain | Apple Swift 6.4, target `arm64-apple-macosx26.0` |
| Process | a plain Rust executable linking the Swift static library — **not** an application bundle |

That last row turns out to be the most important line in this document.

## Measured results

**`probeFoundationModel`: available.** `SystemLanguageModel.default.availability`
returned `.available` on this host, and the mapping produces
`TextModelCapabilities { status: Supported, offline: Yes, can_cancel: Yes,
privacy_class: OnDevice, availability_reason: Available }`. `max_context_tokens`
stays `Unknown`: the framework does not report a context window and inventing
one would be a fabricated limit. `is_transcriber` is false, which is §2.3's
point — this is a text model, never a substitute for transcription.

**`probeSpeech`: the framework is available with 57 locales**, including
`en-US`, `en-GB`, `de-DE`, `fr-FR`, `ja-JP`, `zh-CN`, `pt-BR` and
`hi-IN-translit`. `SFSpeechRecognizer(locale:).isAvailable` was true and
`supportsOnDeviceRecognition` was true, so the mapping yielded
`SttCapabilities { status: Supported, offline: Yes }` with the full locale
list.

**`transcribeFile`: never completed.** Both a synthetic tone and real
synthesized speech (`say` piped through `afconvert` to 16 kHz mono WAV) ran to
the wall-clock budget without the recognizer ever delivering a final result.

## Defect 1: an unauthorized process stalls instead of failing

`SFSpeechRecognizer` requires a separate **authorization** grant, distinct
from availability, and that grant is only obtainable by an application bundle
carrying `NSSpeechRecognitionUsageDescription`. A plain executable is
permanently `notDetermined`.

The failure mode is the problem: an unauthorized recognition task does not
return an error. It simply never calls back. The first version of this bridge
polled a semaphore forever, so the whole call hung.

Fixed two ways:

1. `speechAuthorizationDenial()` checks `SFSpeechRecognizer.authorizationStatus()`
   in **both** `probeSpeech` and `transcribeFile` and refuses up front with
   `permission_denied` plus a discriminator. After the fix the probe returns
   in milliseconds:

   ```text
   == probeSpeech ==
   Err(BridgeError { error: "permission_denied",
                     detail: "speech_recognition_not_authorized_for_this_process" })
   SttCapabilities { status: Unsupported,
                     availability_reason: ProbeFailed { detail: "speech_recognition_not_authorized_for_this_process" } }
   ```

2. Availability and authorization are now visibly different gates. "The
   framework is available with 57 locales" and "this process may use it" are
   two different answers, and conflating them is exactly how a product ends up
   claiming support it does not have.

**Consequence for the product:** Apple speech requires the signed, bundled
application. It cannot be exercised from a command-line harness, so the
A1.3 compatibility evidence has to be captured from the Tauri bundle once
E1.1 ships, with `NSSpeechRecognitionUsageDescription` in the Info.plist.
Until then the honest status is `Unsupported` with a typed reason, which is
what the code now reports.

## Defect 2: no wall-clock bound on a bridge call

Even with authorization, a recognizer that stalls must not be able to hang the
caller. Every long-running entry point now takes `timeout_ms` and returns an
`engine_timeout` document when it elapses, with a ten-minute default. Verified
by observation:

```text
== transcribeFile ==
error: BridgeError { error: "engine_timeout", detail: "20000ms" }
```

The ABI changed to carry the budget; the header documents it as ownership rule
6. The bridge is unreleased, so this is the right moment.

## The ABI, as built

The static library builds with `swiftc` directly — SwiftPM's build system
failed to initialise on this host, and a package manifest buys nothing for a
single-file target. `scripts/build-apple-bridge.sh` produces
`libPlaudonAppleBridge.a` and lists the exported symbols, all nine of which
were verified present with `nm`:

```text
plaudon_apple_bridge_abi_version   plaudon_apple_probe_speech
plaudon_apple_string_free          plaudon_apple_probe_foundation_model
plaudon_apple_new_cancel_token     plaudon_apple_transcribe_file
plaudon_apple_cancel               plaudon_apple_generate_text
plaudon_apple_release_cancel_token
```

Ownership rules are in the header and are the normative contract: every
returned string is library-allocated and released by
`plaudon_apple_string_free`, never by `free`; every input is borrowed for the
call only; callbacks arrive on a library thread; cancellation is cooperative
and a cancelled call never returns a partial transcript. The Rust
`CancelToken` releases its registry entry on `Drop`, so a forgotten cancel
cannot leak.

One linking note for whoever wires this into the bundle: the Swift runtime
needs an rpath, `-C link-arg=-Wl,-rpath,/usr/lib/swift`, or the binary fails to
load `libswift_Concurrency.dylib`.

## Windows exclusion

`crates/ai-apple` compiles on every platform; only `ffi` is
`#[cfg(all(target_os = "macos", feature = "apple-bridge"))]`, and the feature
is off by default. `probe`, which holds all the decision logic, is pure and is
tested in CI with no Apple framework present — 12 unit tests covering every
unavailability case, the unauthorized case, the timeout case, the
guardrail-refusal case and the "unparseable document is not availability"
case.

## Compatibility gates (§11.5)

| Gate | Result |
|---|---|
| Supported Apple Silicon Mac, Apple Intelligence on | Foundation Models **available**; speech framework available but **not authorized for a non-bundled process** |
| Apple Silicon with Apple Intelligence disabled | Not measured. The mapping is implemented and unit-tested: `appleIntelligenceNotEnabled` → `disabled_by_user`, `deviceNotEligible` → `hardware_unsupported`, `modelNotReady` → `model_asset_not_ready` |
| Intel or unsupported Mac | Not measured; no such host available |
| Comparison against whisper.cpp | Blocked: transcription never produced output, and A1.1 has no baseline either |

## Minimum deployment target recommendation (§20.1)

**macOS 26.0.** `SystemLanguageModel` and the `SpeechAnalyzer` family are
gated behind `@available(macOS 26.0, *)`, and the bridge is built with
`-target arm64-apple-macosx26.0`. Older macOS keeps the whisper.cpp path and
gets `platform_unsupported` from the probe — a typed reason, not a crash.

The Rust fallback rule is unchanged and is unit-tested: an unavailable Apple
engine falls back to whisper.cpp and **never** to a cloud engine, because that
would change where the audio goes (§11.6).

## Long-duration and guardrail behaviour: not measured

Spec §20.1's open question about Foundation Models summary quality over a
60-to-180-minute transcript needs a working transcription path first. The
guardrail contract is implemented and unit-tested — a refusal is an error
document, never generated text (§11.4) — but no real refusal has been
observed.
