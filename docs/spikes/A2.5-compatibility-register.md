# A2.5 — compatibility.yaml claim register and risk register

**Status:** complete. **Date:** 2026-10-11. **Spec:** §2.5A, §2.5B, §20, §24.
**Register:** `compatibility.yaml`. **Schema:**
`schemas/compatibility-register.v1.schema.json`. **Loader:**
`crates/source-plaud-device/src/register.rs`.

## How the register works

`compatibility.yaml` is the only source of the compatibility strings the
interface shows. A probed profile is the tuple `(source_type, device_model,
firmware, host_os, os_version, transport, auth_mode)`, and resolution is
**exact on every component**. There is no closest match and no prefix match:
any unmatched tuple is `Resolution::Unmatched`, which grants nothing and
displays "Not evaluated".

A cell cannot claim `supported` without all of: `evidence_level:
observed_on_identified_hardware`, a non-empty `firmware_range`, a non-empty
`os_version_range`, a `test_run_id`, a `last_verified_at` and
`verified_import_recorded: true`. Both the Rust validator and the JSON Schema
enforce that, so an invalid row cannot be committed through either door.

`CompatibilityCell::demoted` expresses invalidation: it drops the status to
`not_evaluated`, clears the evidence and appends the reason. A firmware change
demotes rather than leaving a stale claim (App. B.10 ship gate).

The user-facing vocabulary is fixed at four strings — "Not evaluated",
"Experimental", "Supported", "Known unsupported" — and
`no_rust_or_typescript_source_hardcodes_a_compatibility_label` greps the
whole `crates/` and `apps/` tree to prove none of them is written as copy
anywhere else.

## Risk register

Mirrors spec §20, with the mitigation each risk currently has.

| # | Risk | Severity | Status | Mitigation in place | Evidence |
|---|---|---|---|---|---|
| R1 | Direct BLE never works on macOS or Windows | High | **Open** | Core V1 does not depend on it; every cell is unevaluated and the feature is gated by the register | A2.3, `compatibility.yaml` |
| R2 | A firmware update invalidates a validated cell | Medium | Mitigated | `demoted()` plus a probe on every connection; no cached authorization reuse | `demotion_is_expressible_and_removes_the_claim` |
| R3 | The official CLI changes its output format | High | Mitigated by refusal | `VALIDATED` is empty, so every version fails closed; manual import never depends on the CLI | A2.1 |
| R4 | The CLI package has no licence | Medium | Mitigated | Never bundled, never redistributed; user-installed only | ADR-0009, licensing register |
| R5 | An OpenRouter model cannot be classified | High | Mitigated | `RequestFamily::Unknown` has no builder; the picker shows "Not verified" | A1.2 |
| R6 | A provider privacy route cannot be resolved | High | Mitigated | `PrivacyClass::Unresolved` is not dispatchable; selection fails closed | `a_cloud_engine_with_an_unresolved_route_is_refused` |
| R7 | A cloud request is billed twice by a retry | High | Mitigated | `OutcomeUnknown` is terminal; `auto_retry_safe()` is false after transmission | A1.2 |
| R8 | Apple Intelligence is unavailable on a supported OS | Medium | Mitigated | Availability is a runtime probe with a typed reason; whisper.cpp is the fallback | A1.3 |
| R9 | Opus cannot be decoded, so the device path is useless | Medium | **Open** | Recorded as a known limitation; `UNSUPPORTED_CODEC` is explicit; three closure options documented | A1.4 |
| R10 | A crash leaves a half-registered asset | High | Mitigated | Six-step journal plus a startup reconciler, crash-tested at every step in a real child process | B2.3 chaos suite |
| R11 | A signed URL or credential reaches a log | High | Mitigated | Envelope messages are generated from the code; the redactor removes URLs, dotted and base64 credentials, and sensitive `key=value` pairs anywhere in a token | B1.4, fuzz corpus |
| R12 | A host write is mistaken for one of ours | Medium | Mitigated | `HostWriteBehaviour` refuses a zero-write claim on a read-write mount and names the host entries | A2.4 |
| R13 | A performance target is quoted with no measurement | Medium | **Open** | No baseline exists and a test fails if the document claims one | A1.1 |
| R14 | An unreviewed dependency ships | Medium | Mitigated | `deny.toml` allowlist plus `scripts/license-audit.sh`; unknown licence fails the build | A1.5 |

Three risks remain open: R1 and R13 need hardware, R9 needs a decoder
decision. None of them blocks the core product, which is the point of §1.6's
independent pathways.

## Reproducing the Phase 0 artefacts

```sh
scripts/make-audio-fixtures.sh          # A1.4 corpus
scripts/probe-openrouter.sh catalog     # A1.2 catalog evidence
./scripts/test.sh                       # every spike assertion
```

The register and this risk table are regenerated from the committed evidence
files, not maintained by hand against memory.
