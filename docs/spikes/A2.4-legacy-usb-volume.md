# A2.4 — Legacy USB Note volume and host mount behaviour

**Status:** software complete and unit-tested against a simulated volume;
**no physical device was attached**, so the Note cell stays `not_evaluated`
and the Note Pro and NotePin S cells are `known_unsupported` on vendor
documentation.
**Date:** 2026-10-11. **Spec:** §4.2B, §7.8, App. B.2, B.10 Spike D3.
**Code:** `crates/plaud-usb/`.

## Model verdicts

| Model | USB file access | Source |
|---|---|---|
| PLAUD Note | Conditional on the device's own "Access via USB" setting | Vendor support documentation; upstream reads a mounted `PLAUD_NOTE` filesystem with `NOTES/` and `CALLS/` |
| PLAUD Note Pro | **Known unsupported** — USB is charging only | Vendor documentation (App. B.2) |
| PLAUD NotePin S | **Known unsupported** — no USB recording access | Vendor documentation (App. B.2) |

`VendorModel::may_instruct_user_to_mount` is false for both unsupported
models and for any unrecognized one, so the interface cannot tell a Note Pro
owner to plug in their device. We never toggle the device setting ourselves.

Label matching is **exact** and case-insensitive after trimming.
`PLAUD_NOTE2`, `PLAUDNOTE`, `PLAUD NOTE` and `PLAUD_NOTE_X` all resolve to
`Unknown` and are refused, because a resemblance between volume labels is not
evidence (§2.5B).

## Host mount behaviour: the honest answer

**We cannot promise zero physical writes**, and the code says so structurally.

macOS mounts removable volumes read-write by default and writes its own
metadata: `.Spotlight-V100`, `.fseventsd`, `.DS_Store`, `.Trashes`. Windows
writes `System Volume Information` and `$RECYCLE.BIN`. None of that is ours,
and none of it is under our control.

`HostWriteBehaviour` has three distinct non-unknown values and only one of
them permits a zero-write claim:

| Value | Zero-write claim |
|---|---|
| `MountedReadOnly` | permitted |
| `MountedReadWriteWithHostMetadata { observed_entries }` | refused, with the entries named |
| `MountedReadWriteUnobserved` | refused — a read-write mount can be written at any moment |

What we *can* state is narrower and true: **our code issues no writes**.
`plaud_usb` has no function that creates, moves, truncates or deletes anything
on the volume, `writes_issued_by_this_crate` returns an empty list by
construction, and a test compares a full byte snapshot of the simulated volume
before and after a scan and a read.

## Adversarial cases (§18.6A "USB media")

| Case | Observed outcome |
|---|---|
| Device disappears mid-read | `VolumeDisappeared` → `DEVICE_DISCONNECTED` |
| File shrinks between enumeration and read | `ShortRead { declared, actual }` → `TRANSFER_INCOMPLETE`; nothing is committed |
| Misleading `.WAV` extension over non-audio bytes | Identity comes from the bytes; the name only supplies a codec hint |
| Symlink on the volume | Skipped, never followed |
| Entry resolving outside the volume | `EscapesVolume` |
| 200-character and Unicode filenames (`réunion_会議_🎙.WAV`) | Enumerated and read unchanged |
| Volume without `NOTES/` or `CALLS/` | `LayoutNotRecognized` |
| Volume vanishing before a scan | `VolumeDisappeared`, not an empty listing |

## Quality classification

A `.WAV` on the device volume is `original_device_recording`. Anything else
found there is `Unknown`, and `is_original_fidelity()` is false for it. That
is the §6.3(16) rule: an `.ASR` derivative is never called the original stereo
WAV. The BLE path yields `compressed_device_transfer`, so when the same
recording arrives by both routes the two media candidates attach to one
recording without either overwriting the other (ADR-0006).

## Not measured

A BLE-versus-USB quality and transfer-time comparison needs both paths against
one physical device. Both the `.ASR` sidecar and the original WAV are required,
and we currently cannot decode Opus at all (A1.4), so the comparison is
blocked on a decoder as well as on hardware.

## Serial-containing WAV

§7.8 notes that the source WAV may embed a device serial. We preserve it
unchanged. A sanitized derivative is a separate, explicitly tagged,
user-requested export — never a silent rewrite of the original.
