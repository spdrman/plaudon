# A1.2 — OpenRouter STT and text contract probe

**Status:** complete for everything reachable without a credential; the
per-model exchange probe is opt-in and has not been run.
**Date:** 2026-10-11. **Spec:** §2.2, §2.5B, §2.6, §8.6, §10, App. A.3.
**Code:** `crates/ai-openrouter/`. **Suite:**
`crates/ai-openrouter/tests/contract_fixtures.rs`.
**Evidence:** `tests/fixtures/openrouter/`.

## What was actually measured

`GET https://openrouter.ai/api/v1/models` and
`GET /api/v1/models/openai/gpt-audio/endpoints` are **public and
unauthenticated**, so both were captured for real on 2026-10-11 and the
sanitized responses are committed. No credential was used, and no fixture
contains one — a test asserts that.

- **458 models** in the catalog; **44** declare `audio` in
  `architecture.input_modalities`.
- The audio shortlist is dominated by Google Gemini variants (25 rows),
  plus `openai/gpt-audio`, `openai/gpt-audio-mini`,
  `mistralai/voxtral-small-24b-2507`, `qwen/qwen3.8-omni-flash`,
  several `thinkingmachines/inkling` and `xiaomi/mimo` entries, and the
  `openrouter/auto` routers.

## The finding that shapes the design

**The catalog cannot tell you the request family.** There is no `endpoints`,
`supported_endpoints`, `request_family` or equivalent field anywhere in a
model record, and `supported_parameters` lists chat-completion parameters
only (`max_tokens`, `tools`, `seed`, `response_format`, …). The
`/endpoints` sub-resource adds provider routing — `provider_name`, `tag`,
`context_length`, `max_completion_tokens`, uptime and latency — and still
says nothing about which endpoint contract a model implements. Both absences
are asserted by
`no_catalog_entry_exposes_an_endpoint_family_or_a_retention_control`, so if
OpenRouter adds such a field the test tells us the probe can be simplified.

Consequences, which are exactly the §8.6/§8.6A rules:

1. Every model starts at `RequestFamily::Unknown`. A catalog entry can only
   ever *demote* a model to `Unsupported` (no audio input modality at all).
2. There are two request builders and no generic fallback. A model whose
   family is `Unknown` or `Unsupported` has no builder, so an invalid request
   for it is unrepresentable rather than discouraged.
3. A model is offerable only after an **observed exchange** establishes the
   family and resolves a provider route and a retention control for that exact
   endpoint. Anything less is **Not verified** in the picker.

## Pricing

Audio input is priced on its own key, separate from prompt tokens:
`pricing.audio` on 30 of the 44, and `pricing.input_audio_cache` on 25.
Observed values span three orders of magnitude, from `0.0000000375` to
`0.0001` USD per unit. Router entries report `-1`, meaning the price is not
knowable before routing.

Prices are parsed into a scaled integer at `10^-12` USD (`PRICE_SCALE = 12`),
because the smallest observed value needs nine decimal places and a float
would quietly lose it. A negative or unparseable price is `Known::Unknown`,
never zero — §13.2's "unknown is not zero" applied to the catalog.

## Retention and routing

**Nothing in either public response describes retention, zero-data-retention
eligibility or a data policy.** Spec §10.5 and §10.8 require the privacy route
to be resolved for the specific audio endpoint, not copied from chat
parameters, so this has to come from an authenticated exchange or from
account-level settings. Until it does, `ModelProbeRecord::capability_status`
returns `Experimental` for a model with an observed exchange but an
unresolved route, and `Experimental` is not selectable.

## Error semantics

Classification is implemented and tested against fixtures for 401, 402, 404,
413, 429 with `Retry-After`, 502, a malformed 200 body, a truncated response
and a 308 redirect. The rule that matters is §10.7: once bytes have been
transmitted, an unknown outcome is **terminal**, not retriable, because the
provider may already have billed it. `OutcomeUnknown`, `MalformedResponse` and
`TruncatedResponse` all map to a dispatch state whose `auto_retry_safe()` is
false, and `MalformedResponse`/`TruncatedResponse` additionally require a cost
acknowledgement before a manual retry.

`402 Insufficient credits` maps to `BUDGET_EXCEEDED` rather than a generic
failure, so the interface can say what is actually wrong.

## What has not been done

A real `POST /audio/transcriptions` exchange, which is the only way to
establish request family, accepted codecs, payload ceilings, observed
timestamp fields and the provider route. It needs a funded account, so it is
opt-in:

```sh
OPENROUTER_API_KEY=... scripts/probe-openrouter.sh exchange <model-id> <audio-file>
```

The script sends exactly one request, caps the upload at 5 MB by default, does
not retry, and prints only the status line, the response **field names** and
the routing headers — never a body or a header value that could carry a
credential. Record each result as a row against
`schemas/openrouter-model-record.v1.schema.json`.

Until a row exists with `evidence: observed_exchange`, no OpenRouter model may
be offered for transcription. That is the intended state, not a gap.
