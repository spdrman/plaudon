# A2.1 — Official PLAUD Cloud CLI compatibility

**Status:** complete as a contract and a refusal; **no CLI release has been
exercised**, because that needs a PLAUD account.
**Date:** 2026-10-11. **Spec:** §2.1, §2.6, §4.2, §7.1, §7.2, §7.6.
**Code:** `crates/source-plaud-cli/`.

## Recommendation: (b) postpone automated enumeration

Spec §7.2 offers two outcomes: (a) a version-locked parser with a
compatibility warning, or (b) postpone automated enumeration while preserving
manual import. We recommend **(b) for now, with (a) already built behind an
empty validation table**, because:

- Spec §2.1 forbids assuming JSON mode, stable tabular output, documented exit
  codes or pagination. Every one of those is unverified.
- The npm package listing declares **no licence**, so we cannot bundle,
  redistribute or pin it. The user installs it, and the version they get is
  outside our control.
- Manual import is unconditional V1 and does not depend on the CLI at all, so
  postponing costs the user nothing.

`VersionedParser::VALIDATED` is deliberately **empty**. Every version
therefore resolves to `ParserError::UnvalidatedVersion`, which maps to the
stable `CLI_UNSUPPORTED`. A version is added only together with a golden
fixture captured from that exact release. The test
`no_cli_version_is_validated_yet_so_every_version_fails_closed` makes the
emptiness deliberate rather than accidental.

## What is implemented and tested

**Connector state machine (§7.1).** `UNCONFIGURED → CLI_DETECTED →
AUTH_REQUIRED → AUTHENTICATED → ENUMERATING → READY`, plus `ERROR`,
`EXPIRED_AUTH` and `INCOMPATIBLE_VERSION`. Transitions are total: an
inapplicable event leaves the state unchanged rather than forcing an error, and
a test proves the only path into `READY` is a successful enumeration.

**Invocation safety (§7.1, App. A.4).** The CLI is spawned with an argument
array, never a command string, which matters most on Windows where a command
string is re-parsed by `cmd.exe`. Enforced:

- the executable path must be absolute, canonical and an existing file, so an
  arbitrary or relative program cannot be substituted;
- every argument is rejected if it contains any of `\0 \n \r & | ; \` $ < > ^ " ' % * ?`
  or any control character — none can occur in a legitimate vendor recording
  identifier, and all are meaningful to a shell;
- the child environment is an **allowlist** (`HOME`, `USERPROFILE`, `LANG`,
  `TMPDIR`, `TEMP`), so a poisoned `PATH`, `DYLD_INSERT_LIBRARIES` or proxy
  variable in our own environment cannot change what the vendor tool does;
- an explicit environment override is always rejected;
- stdout, stderr and wall-clock time are all capped.

**Subcommand allowlist.** `CliSubcommand` is a closed enum with four variants:
`--version`, `login`, `files`, `audio <id>`. There is no delete, no settings
write and no firmware command, and none can be constructed.

**Error mapping (§7.6).** Every parser and state failure maps to a stable code
— `CliMissing`, `CliUnsupported`, `AuthenticationRequired`, `MalformedOutput` —
and a test asserts that a vendor error string containing a session token
survives into neither the error message nor the mapped code.

## Open questions this spike could not answer

Each needs an account, and each is recorded as a `known_limitations` entry on
the `plaud_cloud_cli` row of `compatibility.yaml`:

- Does any release offer machine-readable output? If not, option (b) becomes
  permanent rather than provisional.
- What is the `files` field inventory: external id, source version or
  last-modified, device id, tags, vendor transcript availability?
- Does pagination exist, and does it expose a usable cursor?
- What are the exit codes, and are they stable across releases?
- Does a Google or Apple PLAUD login work with the CLI? We will **not** offer
  a token-paste workaround if it does not (§2.1, §7.5).
- Does the CLI expose vendor-generated transcripts through a supported path?
  We must not infer that it does because an unofficial API provides them.

## Procedure for adding a version

1. Capture `plaud --version` and `plaud files` output verbatim into
   `tests/fixtures/plaud-cli/<version>/`.
2. Add `(version, format)` to `VersionedParser::VALIDATED`.
3. Add a test that parses the golden fixture and asserts the field inventory.
4. Record the result in `compatibility.yaml` with a `test_run_id`.

Nothing is auto-detected and nothing is inferred from a neighbouring version.
