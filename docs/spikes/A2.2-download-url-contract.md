# A2.2 — PLAUD download URL contract

**Status:** policy complete and tested; **the URL contract itself is
unobserved**, because it requires an authenticated `plaud audio <id>` call.
**Date:** 2026-10-11. **Spec:** §2.1, §2.6, §7.3.
**Code:** `crates/source-plaud-cli/src/download.rs`.

## What vendor documentation states

`plaud audio <id>` yields a temporary original-audio download URL that expires
in roughly 24 hours (§2.1). Everything else spec §2.6 asks for — scheme,
method, redirect chain, host allowlist, content type, checksum availability,
range and resume behaviour — is **unobserved** and recorded as such in
`UrlContract::undocumented`, whose every runtime-observable field is `None` or
`Unknown`.

## The policy, which does not wait for the observation

`DownloadPolicy::default()` has an **empty host allowlist**, so every download
is refused until a legitimate host has actually been observed and recorded.
Spec §7.3 requires the allowlist to come from observed hosts; guessing a CDN
hostname would be exactly the kind of claim this spike exists to prevent.

Enforced and tested:

| Rule | Behaviour |
|---|---|
| Scheme | Only `https`. `http`, `ftp`, `file` and `gopher` are `SchemeNotHttps`. The scheme is checked before parsing so a downgrade is never reported as a malformed URL. |
| Host allowlist | Exact match or an explicit `*.suffix` wildcard. `cdn.example-vendor.com.attacker.example` and `xcdn.example-vendor.com` are refused. |
| Private destinations | `127.0.0.1`, `0.0.0.0`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `100.64/10` carrier-grade NAT, `198.18/15`, `localhost`, `*.local`, `[::1]`, `[fe80::]`, `[fc00::]` and IPv4-mapped IPv6 are all `PrivateAddress`. |
| Credentials in the URL | `https://user:secret@host/...` is `EmbeddedCredential`. |
| Redirects | The **whole chain** is validated hop by hop, because a redirect is how a forgery escapes a first-URL-only check. A redirect into `169.254.169.254` is refused. More than three hops is `TooManyRedirects`. |
| Body size | Capped; an over-limit declaration is `BodyTooLarge`. |
| Content type | Must be an audio type or `application/octet-stream`; `text/html` is `UnexpectedContentType`, which maps to `IntegrityFailed`. |
| Resume | Only with `RangeSupport::VerifiedWithStrongValidator`. `Unknown` and `NotSupported` both restart from zero (§7.3). |

No error message echoes the URL, asserted by a test: a signed link must not
reach a log or an envelope.

## Staging and commit

The durable path is already implemented and crash-tested in
`plaudon_persistence::journal`: stream to a private `*.part` inside the
archive's own staging directory, hash with a bounded buffer, flush the file and
its directory, record the intent, rename atomically **within the same
filesystem**, then transact. A cross-volume staging path is
`CrossVolumeCommit`, never a copy that looks like a rename. A digest mismatch
quarantines rather than committing, so an interrupted download leaves a
`*.part` and no archive entry.

## What to record when the observation happens

Fill one `UrlContract` per observed host:

- scheme, method and the full redirect chain with final host;
- content type, whether `Content-Length` is present, and any `ETag`,
  `Last-Modified` or checksum header;
- the expiry window actually observed, not the documented approximation;
- whether a `Range` request returns `206` **and** carries a strong validator.
  Only then may `range_support` become `VerifiedWithStrongValidator`.

Then add the observed hosts to `DownloadPolicy::with_hosts`. Until that
happens the connector cannot download anything, which is the correct state.

## Expiry

An expired link must trigger a fresh `plaud audio <id>` call, never a retry of
the stale URL. That is why `LinkExpired` carries the action
`REFRESH_SOURCE_LINK` and is marked retryable, while `IntegrityFailed` is not.
